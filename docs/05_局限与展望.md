# 05 · 系统局限与展望

诚实地说现在**做不到什么**，以及**打算怎么补**。汇报、决策时请把这页一并考虑。

## 一句话定位
这是一个 **PoC（概念验证）**：核心链路都跑通了，用来验证"这条路走不走得通"和持续评估，**还不是上线成品**。下面的局限多数是"现状如此"，不是"永远如此"。

## 现状局限

### 1. 卡片准不准，决定"卡片直答"准不准
卡片是机器从原文自动提炼的，可能有偏差（**卡片保真度**）。所以"卡片直答"快但不保证对；要对结果负责，请用"卡片 + 回原文取证"或 Agentic。
- 展望：用评估看板持续盯"卡片覆盖率 / 下钻失败率"，并让"卡片直答 vs 取证"对比成为常规的卡片校验手段。

### 2. 更新是"整体重建"，不是"只改动的那一点"
新增或修改内容后，知识库是**整体重新生成**，不是只增量更新变化的部分。好处是结果干净一致；代价是更新偏重、且看不出"这次具体改了卡片的哪几处"。
- 展望：做卡片级的"增量 + 变更对照（diff）"，让每次更新能说清"动了什么"。
- 注意：你在冲突面板里的**人工裁决会被记进账本、重建后保留**，这一块已经能跨重建存活。

### 3. 冲突检测只看"同字段、不同值"，还不懂"语义矛盾"
现在能发现的是：同一字段出现了不一样的字面值。还**发现不了**更隐蔽的矛盾，比如"10 天" vs "两周"（值不同字面、其实冲突）、或两张卡的说法互相打架。
- 展望：在冲突复核环节再加一道**大模型语义矛盾检测**，把这类跨值、跨卡的矛盾也挑出来，走同一个红色面板裁决。

### 4. 冲突的默认处理是"先取最新"，必须人来兜底
没人裁决前，系统**暂时取最新的值**——这只是临时占位，不代表它一定对。真正的权威值要靠人在审批页拍板。
- 展望：引入"权威来源优先级"等更聪明的默认策略，减少必须人工介入的量。

### 5. 评估是离线的，且可能用的是 mock 评委 / 演示数据
评估看板的分数，若底层用的是 mock 评委或脱敏合成数据，**不能当真实战绩对外汇报**。系统会用红条/提示标出来。
- 展望：内网接真实大模型 / 真实向量模型后重新跑，得到可汇报的真实指标。

### 6. 检索效果受向量模型 / 重排影响
RAG 那条线"搜得准不准"取决于底层检索与重排能力，演示档用的是轻量替身，效果不代表上线。
- 展望：内网替换为真实向量模型 / 重排模型。

### 7. 卡片不可自由手改（是取舍，也是局限）
为保证"每个字可追溯"，卡片是只读的，不能像文档一样直接编辑（要改得动原料，见 [04](04_知识库增删改流程.md)）。好处是杜绝无依据内容，代价是"想快速改一个字"没那么直接。
- 展望：在"可追溯"前提下，提供更顺手的纠错入口（目前冲突面板的"选定值"已是其中一种）。

### 8. 接入不是实时自动同步
Confluence 改了之后，需要**重新跑一遍流水线**才会反映进来，不是改完即时生效。
- 展望：做定时 / 触发式同步，并在有未裁决冲突时主动提醒相关人。

### 9. 依赖人工闸，规模化有成本
"词表审批"和"冲突裁决"都需要人参与——这是质量的保证，但内容量很大时是持续的人力投入。
- 展望：用大模型把"明显该合并 / 明显低风险"的先自动处理，把人留给真正需要判断的少数。

## 一句话总结
**强在可追溯、有人工闸、答不出来会老实说"没依据"；弱在更新偏重、卡片保真度有限、语义级矛盾和真实指标还要补。** 把它当"会标出处、会喊不确定"的助手用，重要结论仍以"卡片 + 回原文取证"并人工复核为准。
