# 02 · 每个界面怎么用

逐页、逐按钮的操作说明。看到不认识的控件，回这里查。

---

## 一、实时问答（主页）

这是你最常用的页面：提问 → 看答案 → 看它怎么得出答案。

### 顶部
- **实时问答 / 评估看板 / 卡片路径**：三个切换入口。
- **右上角状态 + "连接后端"按钮**：
  - "已连接后端" = 正常。
  - "离线演示" = 没连上后端，正在用内置脱敏数据（仅供观摩）。点按钮可在"连真实后端 / 用离线演示"之间切换。

### 左侧"选择提问方式"
- **Golden Set / 自由提问**：
  - *Golden Set*：从预置的标准问题里挑一个。好处是右边能同时显示"人工标准答案"做对比。
  - *自由提问*：自己打字问任意问题。
- **回答方式（三族）**：决定用哪条知识线回答。三选一（详见 [03](03_三种回答模式.md)）：
  - **Agentic（自动路由 · 推荐）**：系统自己判断该走哪条路。默认就用它。
  - **RAG（检索原文生成）**：直接从原文小段里检索 + 生成。
  - **卡片库（审批卡）**：用整理好的卡片回答。选它会多出一个**子模式**：
    - **卡片直答**：直接读卡片里已提炼的字段值，不回原文。快，像查词条。
    - **卡片 + 回原文取证**：卡片只用来定位主题，答案回到原文段落逐句生成，可追溯。
- **对照基线（模型直答 · 无 grounding）**：让大模型**只凭自己的知识**回答，不看公司知识。仅作对照，**最不可信**，别当正式答案。
- **问题语言**：中文 / English（Golden 模式下生效）。
- **域筛选（可选）**：把回答限制在某个业务域内（比如只在"请假"相关知识里找）。
- **Debug 模式**：勾上后，答案会附带召回链路每一跳的细节。给想深究的人用，普通使用可以不勾。
- **当前问题 + 开始回答**：输入框 + 提交按钮。

### 右侧"回答与执行轨迹"
- **GOLD ANSWER**：人工核验的标准答案（只有 Golden 模式有）。
- **LLM ANSWER**：系统的回答，流式逐字显示。
- **执行轨迹**：一步步亮出系统"是怎么想的"（思维链）——先匹配到哪张卡、判断是什么类型的问题、有没有回原文取证等。
- **证据来源**（最重要的判断依据）：一块小标签，四选一告诉你这次答案的底气来自哪：
  - **卡片字段（未回原文）**：答案来自卡片里提炼的值，没回原文核对 → 看[卡片保真度]。
  - **原文段落（已回原文取证）**：答案回到了 Confluence 原文逐句核对 → 最踏实。
  - **全库检索（RAG，未经卡片）**：直接从原文库检索得来。
  - **无可验证证据**：系统没找到能支撑的依据，于是**拒绝瞎编**（这是好事，不是 bug）。
  - 旁边还有「**是否回原文**」标记，告诉你有没有做"回原文取证"这一步。
- **证据列表**：列出用到的原文段落 / 卡片字段 / 下钻原文，每条可点回出处。

> 小贴士：如果答案说 **NO_ANSWER / 无可验证证据**，代表知识库里确实没有可靠依据。这比硬编一个答案更安全。

## 二、评估看板（主页内切换）

把几种回答方案在**同一批标准问题**上跑分、横向对比。非技术使用者了解即可：

- **三族横向对比**：Agentic / RAG / 卡片库 谁的召回、忠实度、卡片覆盖更好。
- **Variant Ladder / Card Value / Golden Types**：更细的分项指标。
- 用来回答"哪种方案更靠谱"，是给方案评估、汇报用的。
- ⚠ 如果数据是脱敏 mock，看板会提示，**别拿 mock 分数对外汇报**。

## 三、卡片路径（Card Explorer）

翻看一张张卡片的内部结构，以及"一次回答是怎么一层层钻进去的"。

- **顶部「载入 cards_index.json」**：从本地文件临时载入一批卡片来看（排查用）。
- **左侧卡片列表**：按业务域分组，点任意卡片看详情。可搜索。
- **卡片详情（结构视图）**：一张卡 = 主题 → 小节 → 一条条事实（带"出处/复制 anchor"）。
  - 卡片上可能有**标签 chip**，比如"该卡覆盖不全（已回退 RAG）"——提示这张卡有局限。
- **结构 / 地图 两个视图**：
  - *结构*：竖向看一张卡的内容。
  - *地图（知识地图）*：圆点=一张卡，连线=两张卡明确相关，看知识之间怎么连。点圆点跳回该卡。
- **提问框**：在这页问问题，会把"这次回答用到的卡片和证据"在结构里高亮出来，演示下钻路线。
- ⚠ 顶部若出现**红色「脱敏 DEMO 卡片」**条，说明这批卡不是真实内网数据。

## 四、词表审批 / 候选 topic 审批（审批页）

维护知识"骨架" + **复核字段冲突**。分两块：

### A. 字段冲突复核（页面顶部，红色那块）—— 经后端打开才出现
当同一字段在不同页面/版本里出现**多个不同取值**时（比如门户链接老页写 A、新页写 B），系统会：
- 暂时先取**最新**的值，并把冲突**红色突出**列在这里；
- 让**大模型先复核**：给出"建议采用哪个值 + 理由 + 风险高/中/低 + 置信度"。

你要做的：
1. 看每张**红色冲突卡**：并排列出所有候选值（带来源页、版本、日期），标出"系统暂取最新"。
2. 看大模型建议（尤其注意**风险=高**的——通常是数字明显不同，自动取最新可能漏掉一次真实变更）。
3. 拍板：点 **「采纳建议并冻结」**，或对某个候选点 **「选这个」**。
4. 该冲突变**绿色"已裁决"**，计数减一。你的决定**写进账本，以后重建知识库也不会丢**。
- 若以后又来了**新的取值**，这条冲突会重新变红并提示"有新值"，请再确认一次。

### B. 词表审批（防止知识碎片化）—— 纯前端，可离线用
新页进来后会产生一批"候选主题"。这块让你确认它们：
- 先**载入现有冻结词表**当合并目标；
- 把"其实是老主题换了个名"的新候选 **合并到已有**（避免同一件事裂成好几张卡）；
- 或**降级为子条目** / **保留为新主题** / 丢弃；
- 最后**导出** `keyword_table.jsonl`，交给维护同事重建卡片。

> 一句话：A 块管"同一字段哪个值对"，B 块管"该不该新建一张卡 / 怎么合并"。
